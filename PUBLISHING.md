# Как загрузить и опубликовать

## Удобнее всего — через GitHub Desktop

Подготовленная папка содержит много исходных файлов. Надёжнее загружать её через GitHub Desktop, а не переносить файлы по одному через сайт.

1. В GitHub Desktop выберите **File → Add local repository**, затем подготовленную папку. Если вы распаковали ZIP и Desktop сообщает, что это ещё не репозиторий, выберите предложенное **Create a repository here**.
2. Выполните первый Commit, например `Portfolio demo`.
3. Нажмите **Publish repository**, назовите репозиторий `golden-tablet` и снимите **Keep this code private**, если хотите публичный репозиторий.
4. После публикации выполните настройку Pages ниже. Если загружаете файлы через сайт GitHub, сначала создайте репозиторий и поместите содержимое папки в его корень.

[Официальная инструкция GitHub Desktop](https://docs.github.com/en/desktop/adding-and-cloning-repositories/adding-a-repository-from-your-local-computer-to-github-desktop).

## Один раз на GitHub

1. Создайте **публичный** репозиторий. Можно назвать его `golden-tablet`. Основная ветка — `main`.
2. Загрузите **содержимое подготовленной папки** в корень репозитория. Не помещайте всё внутрь ещё одной папки. В корне должны быть `package.json`, `pnpm-lock.yaml`, `apps`, `packages`, `scripts` и `.github`.
3. Откройте **Settings → Pages → Build and deployment → Source → GitHub Actions**.
4. Откройте **Actions → Publish portfolio demo → Run workflow**. Если сборка уже запустилась после загрузки, дождитесь её завершения; после настройки Pages можно запустить ещё раз.
5. В завершившемся запуске появится ссылка на сайт. Её можно отправлять вместе с резюме.

Имя репозитория менять в коде не нужно. Загрузка ZIP как одного файла не опубликует приложение: архив сначала нужно распаковать, а затем загрузить его содержимое.

## Что публикуется

Workflow собирает `apps/demo` и отправляет в Pages только статические файлы. Публичному посетителю не нужны Node.js, pnpm, пароль или ключи. Он работает со своей копией примеров в браузере; другие посетители её не видят.

В репозитории не должно быть `node_modules`, `.next`, `.next-fast`, `data`, резервных копий, `.env`, файлов `.db` или личных вложений. Всё это исключено из подготовленной папки и из `.gitignore`.

## Обновить демо

Измените исходники и загрузите изменения в `main`. Сайт пересоберётся автоматически. При изменении начальных примеров посетитель может нажать «Сбросить демо», чтобы увидеть исходные данные заново.

Демоданные уже включены в `apps/demo/src/generated/demo-data.json`. В GitHub Actions не нужно запускать локальную SQLite-версию или экспортировать базу.

## Проверить локально поведение Pages

```sh
pnpm install --frozen-lockfile
pnpm pages:build
pnpm pages:preview
```

Команда покажет адрес просмотра. При сборке в GitHub путь сайта определяется из имени репозитория автоматически. Обработчик `404.html` сохраняет переходы прямо в разделы приложения.
